# 2026-10-17: Reproducing rustfmt 1.10.0

Rust 1.99.0 ships rustfmt 1.10.0 (#107). `rustfmt_version = "1.10.0"` now reproduces it; the
default stays 1.9.0. This record continues the classes of
[the rustfmt versions record](2026-10-14-autoresearch/rustfmt-versions.md) (F1–F14,
P1–P8) with the differences between 1.9.0 and 1.10.0, and two 1.8.0 classes found on the way.

## Current State

- **Toolchains (measured, `--version`).** `rustfmt 1.10.0-stable (b940084d7e 2026-09-28)` with
  `rustc 1.99.0 (b940084d7 2026-09-28)`; against `rustfmt 1.9.0-stable (2d8144b788
  2026-07-07)` (Rust 1.97.0) and `rustfmt 1.8.0-stable (6b00bc3880 2025-06-23)` (Rust
  1.88.0).
- **Method.** The rustfmt sources of the two toolchains (`src/tools/rustfmt/src` at the
  `1.97.0` and `1.99.0` tags of rust-lang/rust) diffed file by file, every hunk classified as formatting, acceptance, internal (AST field
  renames, `--file-lines`), or nightly-only; then the two binaries run on the fixtures (1220
  compared) and on the 9528 `.rs` files of the local registry under 400 KB, at editions 2024
  and 2021, and a probe written for each class. Each class below was confirmed by chloro's
  output matching both releases on its probe.
- **What the corpora show (measured).** rustfmt 1.9.0 and 1.10.0 differ on 1 fixture at
  edition 2024 (`parser/ok/0051_parameter_attrs.rs`, F15), now in
  `snapshots/ra-1.10.0/`, and on 2 of 9528 registry files at both editions (the same
  `0051_parameter_attrs.rs` and `inline/ok/impl_item_const.rs`, P9, in `ra_ap_parser`'s test
  data). The other classes come from the source diff; nothing in either corpus exercises
  them.
- **Results (measured).** `conform -i -V 1.10.0`: 1220/1220, none non-idempotent;
  `config_matrix -n 1220` against rustfmt 1.10.0 with `rustfmt_version=1.10.0` and the 31
  option values, plus `hex_literal_case` Upper and Lower: 1238 of 1238 for each (a file
  rustfmt rejects compared as its input). `config_matrix --root ~/.cargo/registry/src`
  with `rustfmt_version=1.10.0`, the local registry's 9547 files (285 crates): 9547 of 9547
  at editions 2024 and 2021. The reproducers run at
  three releases and two editions: 246 triples, all identical. The default release's
  outputs are unchanged (`bench --check`, 0 of 1238; `conform -i` at 1.9.0 and 1.8.0,
  1220/1220).

### Formatting classes

| class | input | rustfmt 1.9.0 | rustfmt 1.10.0 | source (1.10.0) |
|---|---|---|---|---|
| F15 attributes of an unnamed parameter | `fn a(x: i32, #[attr] ...);`, `fn(#[attr] u8)` | `fn a(x: i32, ...);` (attribute dropped) | kept, combined as for a named parameter | `items.rs:2364` `Param::rewrite_result` |
| F16 `//` comment in an empty parameter list of an overflowing header | `fn long…( // c\n) {}` | overflow tested first: `)` on the comment's line | comment tested first: `)` on a new line (PR #6840) | `items.rs:2595` `rewrite_fn_base` |
| F17 range patterns | `1. ..=2.`, `3. ..` | the expression rules of 1.9.0 | `range.rs` `rewrite_range`, shared with expressions: a space before the operator after a literal ending in `.` | `patterns.rs`, `range.rs` |
| F18 `const` of a trait impl | `const unsafe impl Trait for X {}` | `unsafe impl const Trait for X {}` | `const unsafe impl Trait for X {}` | `items.rs:959` `format_impl_ref_and_type` |
| F19 comments between `macro_rules!` and the name | `macro_rules! /* c */ foo { .. }` | comment dropped | kept as written (`header.rs` `format_header`, new in 1.10.0) | `macros.rs:456` `rewrite_macro_def` |
| F20 `super let` | `super   let x=1;` | statement copied as written | formatted as a `let` with `super ` before it | `items.rs:67` |
| F21 `line_start` after trailing whitespace in missed code | — | advanced only past code | advanced always (written for `--file-lines`) | `missed_spans.rs:367` |
| F22 `impl const S {}` (inherent) | `impl<T> const S<T> {}` | `const impl<T> S<T> {}` | as written: rustc 1.99.0 reads `const S` as the self type, a trait object | rustc's parser |

F21 changes no output found: the rest it skips is whitespace that the last snippet trims.
It is ported so that the control flow stays rustfmt's.

`hex_literal_case` is stable in 1.10.0 (`config/mod.rs`): chloro takes it from
`rustfmt_version = "1.10.0"`, and before that keeps it unstable (an error on the command
line, a warning in a file). `doc_comment_code_block_small_heuristics` is new and unstable
in 1.10.0; chloro calls it unknown before 1.10.0, as those releases do.

### Acceptance classes

| class | input | rustc 1.88.0 (rustfmt 1.8.0) | rustc 1.97.0 (1.9.0) | rustc 1.99.0 (1.10.0) |
|---|---|---|---|---|
| P9 `const` after `impl` in a trait impl | `impl const Trait for T {}` | formats | formats | exit 1 "expected a trait, found type" |
| P10 `const` before `impl` | `const impl S {}`, `const impl Trait for T {}` | exit 1 "expected identifier, found keyword `impl`" | formats | formats |

P10 and the 1.8.0 half of F22 (rustfmt 1.8.0 also writes `impl<T> const S<T>`) were not
found by the 1.8.0 work: no file of either corpus has a `const` impl other than
`impl_item_const.rs`, which all three releases treat alike apart from P9. Both are fixed
here for 1.8.0 too.

### Not reproduced

- **Nightly only**: `cfg_select!` formatting (behind `is_nightly_channel!()`), style edition
  2027, pattern types, `mut` restrictions.
- **`--file-lines`**: the other hunks of `missed_spans.rs`.
- **Parser gap**: `default const impl Trait for T {}`, which rust-analyzer reads as a
  `const` item (ledger case 24).

### Structure

- `RustfmtVersion::V1_10_0`; the version checks are `>= V1_10_0` beside the existing ones,
  each with its class and the 1.10.0 source line.
- `formatter/header.rs` ports `header.rs` (only `HeaderPart::new`, the one constructor
  chloro needs).
- `Config::set` refuses `hex_literal_case` other than `Preserve` before 1.10.0, and a
  release before 1.10.0 while one is set, so either order of the two options gives one
  answer or one error. The command line applies `rustfmt_version` first: in `--config`, and
  in a `rustfmt.toml`, where that of `--config` wins over the file's.
- The cache key has one more byte (the case), so the caches of earlier builds are not read.

## Missing

- The default release. Switching it to 1.10.0 changes the output of every project that
  formats with chloro today; it is left to a release decision.
- A registry comparison at 1.10.0 over the full 577-crate manifest; the local registry
  (285 crates) was used.
