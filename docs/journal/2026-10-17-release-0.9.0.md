# 2026-10-17: Preparing the 0.9.0 release

0.9.0 releases the performance and conformance work of
[#88](https://github.com/lmmx/chloro/pull/88) (see the
[handoff](2026-10-17-handoff.md)), with the documentation site and changelog of #89, #93 and
#94, and the work merged today: #96 (the front page's tagline) and #98 (`chloro --version`
and the `vs-rustfmt` recipes). The release itself is `just ship 0.9.0` from master, run by
the owner; this entry records the state just before it.

## Current State

- **`chloro --version`** (#98) prints the plain version only for a build of the release:
  `chloro/build.rs` checks, at compile time and with the local `git` only, that HEAD is the
  commit of the tag `chloro-v<version>` (annotated tags resolved to their commit) and that
  `git status` shows no changes to the binary's inputs, or that a packaged crate's
  `.cargo_vcs_info.json` records a clean source. Any other build prints `<version>-dev` with
  the short commit and `dirty` where known; a source with neither kind of metadata prints
  `(unknown source)`. The Cargo version is unchanged. Tested on a clone (untagged, dirty,
  annotated tag, tag plus dirty, a commit past the tag, packed refs) and on a `git archive`
  copy with and without a `.cargo_vcs_info.json`.
- **`just reinstall`** bakes a build ID into the binary, a hash of the binary's input files
  as they are on disk, `Cargo.lock`, HEAD and its tags, the toolchain and the install
  command. `just vs-rustfmt DIR` and `just vs-ruff` compare it with `just build-id` and
  reinstall only when they differ, so a benchmark never times a stale install and never
  rebuilds a fresh one.
- **`just vs-rustfmt`** gives chloro the files `cargo fmt --all -- --check -v` reports
  formatting, so each tool formats each file once. Running `rustfmt` on every `.rs` file of
  a project instead formats module files repeatedly (on ruff, 7,332 passes over 2,028 files),
  which is where an earlier figure of 86 times faster came from.
- **The ruff measurement** (owner's 20-core workstation, rustfmt `1.10.0-stable (b940084d7e
  2026-09-28)`, 2,008 files, 5 runs): chloro 212.3 ± 4.8 ms on 20 threads, 1598.3 ± 12.6 ms
  on one, `cargo fmt --all -- --check` 5633.0 ± 104.8 ms; peak memory 89.9, 16.2 and 194.5
  MiB. One thread is 0.284 of `cargo fmt`'s time, inside the one-core range of measurement
  M6 (0.21–0.35), though on another machine and with fewer runs.
- **The exit-code check** behind that measurement, on ruff at `8d122c1` (2,023 files) with
  the same toolchain: `cargo fmt --check` exits 0; `chloro --check` reports one file,
  `crates/ruff_unicode_names2_generator/src/phf.rs`, whose three `\r\n` line endings among
  `\n` ones rustfmt leaves as they are and chloro converts (#97, already open). rustfmt's
  `--check` and `--write` both treat the file as formatted, while `--emit stdout` prints it
  with `\n` throughout.
- **The front page** shows the conformance figure on its own, then M6's nine crates (five
  rust-analyzer crates, tokio, regex-syntax, clap_builder, winnow) against rustfmt 1.9.0:
  rustfmt first as the baseline, then chloro on one core and on four, with bars of wall time
  (rustfmt's as the full bar, spanning the nine crates), speedups and peak memory. The ruff
  measurement is a sentence below it that names its conditions, rather than a second panel:
  side by side, the two read as one comparison, though they differ in rustfmt version
  (1.9.0 and ruff's pinned 1.10.0), machine, method, and range against single value. The
  Performance page has a section on the ruff measurement.
- **Release checks**, on master at `7f9f552` (the documentation changes of the release pull
  request do not touch code): `cargo test --workspace --all-features` and `just clippy` pass;
  the conformance results are in the release pull request.
